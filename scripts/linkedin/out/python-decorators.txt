Decorators look like magic until you see that @timed is just slow_thing = timed(slow_thing). Then the whole feature becomes obvious.

In Python, functions are values: you can pass them around and return them. A decorator is a function that takes a function and returns a new, wrapped function. The @ syntax is shorthand for the reassignment. Nothing more mystical than that.

If you repeat the same boilerplate around many functions, a decorator is the DRY answer.
